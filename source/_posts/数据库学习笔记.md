## 1. 介绍：数据库是什么，为什么要有数据库

数据库本质上就是一个**运行在硬盘上的文件系统**，一般我们自己编写的代码，数据存在List/Map里面，断电或者重启数据就没了，另外普通文件存在硬盘里面，比如说txt或则excel，能保存但是很难查找。而数据库（MySQL）中的数据存在硬盘里，但有一个管家管着，利用索引技术，很快就能找到。

可以用excel来类比下关系型数据库：

| **数据库术语**        | **Excel 对应**              | **说明**                                        |
| --------------------- | --------------------------- | ----------------------------------------------- |
| **Database (数据库)** | **一个 Excel 文件 (.xlsx)** | 比如 `meituan_data.xlsx`                        |
| **Table (表)**        | **Sheet (工作表)**          | 一个文件里可以有“用户表”、“订单表”、“商品表”    |
| **Column (列/字段)**  | **表头 (第一行)**           | 规定了每一列存什么，比如 `Name`, `Age`, `Price` |
| **Row (行/记录)**     | **数据行**                  | 每一行就是一个具体的订单或用户                  |

然后要说明的是，这里是MySQL的学习笔记，另外还有Oracle或者其他一些自研数据库管理工具自行学习即可。

#### 3.2.3 改 (UPDATE) —— 比如张三充值了

我们要把 **ZhangSan** 的余额改成 `200.0` 元。

**警告：不要忘记写 `WHERE`**！

- **错误写法：** `UPDATE users SET balance = 200;` （完蛋了，所有人的钱都变成 200 了）
- **正确写法：** 必须加锁，指定只改某一个人。

**实战代码：**

```sql
-- 任务：把用户名为 'ZhangSan' 的人，余额改为 200
UPDATE users 
SET balance = 200.0 
WHERE username = 'ZhangSan'; 
-- 也可以写 WHERE id = 1; (用 ID 更精准)
```

#### 3.2.4 删 (DELETE) —— 比如王五注销账号了

我们要把 **WangWu** 从表里彻底删掉。

- **错误写法：** `DELETE FROM users;` （完了，全库清空，准备跑路吧）
- **正确写法：** 指定只删某一个人。

**实战代码：**

```sql
-- 任务：删除用户名为 'WangWu' 的记录
DELETE FROM users 
WHERE username = 'WangWu';
```

#### 3.3.1 条件筛选 (`WHERE` 的进阶)

- **场景**：找出所有余额大于 1000 元的“大款”。
- **符号**：`>` (大于), `<` (小于), `>=` (大于等于), `!=` (不等于)。

**实战代码：**

```sql
-- 找出余额大于 500 的用户
SELECT * FROM users

```

#### 3.3.2 排序 (`ORDER BY`) —— 谁最有钱？

默认的数据是按 ID 排的，我们想按“余额”排。

- **语法**：`ORDER BY 列名 [ASC|DESC]`
  - **ASC** (Ascending)：升序（从小到大，默认）。
  - **DESC** (Descending)：降序（从大到小）。

**实战代码：**

```sql
-- 按余额从大到小排序（看看谁是首富）
SELECT * FROM users 
ORDER BY balance DESC;
```

#### 3.3.3 分页 (`LIMIT`) —— 只看前几名

这是开发**最常用**的语句。手机 App 一页只显示 10 条外卖，就是用这个实现的。

- **语法**：`LIMIT 数量`

**实战代码：**

```sql
-- 找出最有钱的 3 个人 (组合拳：先排序，再取前3)
SELECT * FROM users 
ORDER BY balance DESC
LIMIT 3;
```

### 3.4 SQL统计与聚合：想看报表怎么办？

> 解决场景：
>
> “咱们现在的用户总共有多少人？”
>
> “用户账户里总共存了多少钱？”
>
> “平均每个用户有多少钱？”
>
> “最有钱的人有多少钱？”

### 3.4.1 核心五大函数

| **函数**    | **英文** | **作用**   | **对应 Excel** |
| ----------- | -------- | ---------- | -------------- |
| **COUNT()** | Count    | **数人头** | `=COUNT()`     |
| **SUM()**   | Sum      | **求和**   | `=SUM()`       |
| **AVG()**   | Average  | **算平均** | `=AVERAGE()`   |
| **MAX()**   | Maximum  | **最大值** | `=MAX()`       |
| **MIN()**   | Minimum  | **最小值** | `=MIN()`       |

### 3.4.2 示例

```sql
-- 统计 users 表里一共有多少行数据
SELECT COUNT(*) FROM users;

-- 一次性查出：总金额 (Total) 和 平均金额 (Average)
-- AS 是给结果列起个中文别名，方便看
SELECT 
    SUM(balance) AS 总金额, 
    AVG(balance) AS 平均金额 
FROM users;

-- 查出最有钱和最穷的余额是多少
SELECT 
    MAX(balance) AS 首富余额, 
    MIN(balance) AS 最穷余额 
FROM users;
```

**进阶：待条件的统计：** 只想看**余额在 1000 元以上**的那些大客户，他们的**平均余额**是多少？

```sql
-- 错误解法：AVG() 是一个计算器，它只负责算数，不负责筛选。你不能把 WHERE（筛选条件）塞进 AVG 的肚子里。
select
	AVG(where BALANCE > 1000) as 大于1000平均
from users;

-- 先筛选再计算
SELECT 
    AVG(balance) AS 大于1000平均 
FROM users 
WHERE balance > 1000;  -- 先筛选，后计算
```

**为什么这里是先筛选后计算？**

对与sql语句来说，sql语法有固定的书写顺序：

```sql
SELECT
DISTINCT
FROM
JOIN
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT` / `OFFSET
```

但是也有固定的执行顺序：

```sql
FROM / JOIN —— 确定数据源
WHERE —— 筛选原始数据（无法使用聚合函数结果）
GROUP BY —— 对筛选后的数据分组
HAVING —— 筛选分组后的结果（可以使用聚合函数结果）
SELECT —— 计算并展示结果（起别名、聚合计算等）
DISTINCT —— 去重最终结果
ORDER BY —— 对最终结果排序
LIMIT / OFFSET —— 限制返回结果的数量
```

### 3.5 分组统计(`GROUP BY`) —— SQL 最强大的功能

> 场景：“别光给我看总平均，我想看 **每个城市** 的用户总资产是多少？是北京的钱多，还是深圳的钱多？”

#### 3.5.1 第一步：数据改造 (DDL)

我们需要先给表“装修”一下，加一列 `city`，并且给每个人分配一个城市。

```sql
-- 1. 给 users 表增加一列 'city'，最多存10个字

-- 2. 给大佬们分配城市
UPDATE users SET city = 'Hangzhou' WHERE username = 'MaYun';
UPDATE users SET city = 'Shenzhen' WHERE username = 'Pony';

-- 3. 给剩下的小伙伴分配到 Beijing (一次更新多人)
UPDATE users SET city = 'Beijing' WHERE city IS NULL;

-- 4. 查一下看看效果
SELECT * FROM users;
```

------

#### 第二步：分组查询 (`GROUP BY`)

现在我们要用到 SQL 的灵魂语法：**“按......分组”**。

**语法公式：**

```sql
SELECT 
    分组列名, 
    聚合函数(...) 
FROM 表名 
GROUP BY 分组列名;
```

**任务：统计每个城市的总资产** 请尝试写出这条 SQL：

1. 我们要查的是 `city` 和 `SUM(balance)`。
2. 要按照 `city` 进行分组。

**参考代码：**

```sql
SELECT 
    city AS 城市, 
    SUM(balance) AS 城市总资产 
FROM users 
GROUP BY city;
```

## 4. 多表关联与数据库设计

> **核心痛点：**现实中的数据散落在不同的表里（比如订单在表A，用户在表B），怎么连起来查？
>
> 关键掌握：
>
> 1. 多表关联初体验（外键的概念）
> 2. 内连接(`INNER JOIN`)
> 3. 外连接 (`LEFT JOIN`)
> 4. 子查询 (Subquery) —— 套娃式查询。
> 5. 数据库设计范式 (一对一、一对多、多对多)。

### 4.1 多表关联

**数据库设计的哲学是”各司其职“。**

- **用户表 (`users`):** 只存人的信息（名字、余额）。
- **订单表 (`orders`):** 只存订单的信息（单号、金额）。
- **关联桥梁：** 在订单表里留一个 **“线索”** 指向用户表。

这个“线索”，在数据库里叫 **外键 (Foreign Key)**。

#### 4.1.1 创建订单表

```sql
-- 1. 建表：订单表
CREATE TABLE orders (
    id INT AUTO_INCREMENT PRIMARY KEY, -- 订单自己的身份证
    order_no VARCHAR(20),              -- 订单号 (比如 'ORD-001')
    price DOUBLE,                      -- 订单金额
    user_id INT                        -- 【关键】这就叫“外键”，存的是用户的 ID
);

-- 2. 塞数据：给张三 (id=1) 和 马云 (id=4) 下单
-- 注意：我们只存 user_id，不存名字！
INSERT INTO orders (order_no, price, user_id) VALUES ('Meituan-001', 25.0, 1); -- 张三的单
INSERT INTO orders (order_no, price, user_id) VALUES ('Meituan-002', 40.0, 1); -- 张三的单
INSERT INTO orders (order_no, price, user_id) VALUES ('Meituan-003', 99.0, 4); -- 马云的单
INSERT INTO orders (order_no, price, user_id) VALUES ('Meituan-004', 10.0, 4); -- 马云的单

-- 3. 还有一单是 Pony (id=5) 的
INSERT INTO orders (order_no, price, user_id) VALUES ('Meituan-005', 100.0, 5);

-- 4. 验证一下
SELECT * FROM orders;
```

**Q：如果我现在只有这张 `orders` 表，能知道 `user_id = 1` 的那个人叫什么名字吗？**

**A：** 可以，这就是 **“关系型数据库”** 的精髓：

- **数据是分散的：** 为了节省空间、方便维护，我们将信息拆到了不同的表里。
- **逻辑是关联的：** 虽然 `orders` 表里只有冷冰冰的数字 `1`，但它像一个路标，指向了 `users` 表里的 `id=1`（也就是 ZhangSan）。

现在要看一张**完整的订单表**，要求显示：**订单号、价格、下单人的名字**（注意：不是 ID，要名字！）。

这就需要数据库做一个动作： 拿着 `orders` 表里的 `user_id`，去 `users` 表里找对应的 `id`，找到了就把那一行的 `username` 拿过来拼在一起。

**核心原理：内连接 (Inner Join)**

最常用的 Join 叫 `INNER JOIN`。它只保留**两边都能匹配上**的数据。

- 如果 `orders` 里有个 user_id = 99，但 `users` 表里没有 99 号人，这条数据会被**扔掉**。
- 如果 `users` 里有个 WangWu，但他没下过单，这条数据也会被**扔掉**。
- **它只取“交集”。**

#### 4.1.2 语法和示例

```sql
SELECT 
    表A.列名, 
    表B.列名 
FROM 表A
INNER JOIN 表B 
    ON 表A.外键 = 表B.主键; -- 这一行是灵魂！告诉数据库怎么对接
    
    -- 任务：查询订单详情，并显示用户名
SELECT 
    orders.order_no AS 订单号,
    orders.price    AS 价格,
    users.username  AS 下单人    -- 注意：这里是从 users 表拿的数据！
FROM orders
INNER JOIN users 
    ON orders.user_id = users.id; -- 桥梁：订单的 user_id 等于 用户的 id
```

### 4.2 左连接 (`LEFT JOIN`) 

**Q：为什么要引入左连接？**

A：想看所有注册用户，如果下过单，就显示订单号，如果没下过单，也把名字列出来，如果用内连接，这些没下过单的人就直接消失了。

#### 4.2.1 核心原理

`LEFT JOIN` 的逻辑是：**以左边的表为主**。

- 左表（写在 `FROM` 后面的）里的数据，**不管能不能匹配上，全部都要保留**。
- 右表（写在 `JOIN` 后面的）里的数据，能匹配上就显示，匹配不上就填 **NULL (空)**。

#### 4.2.2 语法和示例

```sql
SELECT 
    users.username, 
    orders.order_no 
FROM users           -- 【左表】老大！所有用户都要保留
LEFT JOIN orders     -- 【右表】跟班。有就显示，没有就空着
    ON users.id = orders.user_id;
    
    
 -- 任务：查询所有用户的订单情况（包括没买过的）
SELECT 
    users.username AS 用户名,
    orders.order_no AS 订单号,
    orders.price    AS 金额
FROM users
LEFT JOIN orders 
    ON users.id = orders.user_id;  
```

如图所示：

![外键示例](/images/mysql/sql_4.png)

如果只看没下过单的人呢？

```sql
SELECT 
    users.username, 
    orders.order_no 
FROM users
LEFT JOIN orders 
    ON users.id = orders.user_id
WHERE orders.order_no IS NULL;  -- 【关键】只把那些“空”的抓出来
```

### 4.3 子查询(Subquery) —— 套娃战术

>  场景：
>
> 查询所有余额高于平均值的用户	

#### 4.3.1 子查询场景错误写法

错误写法：

```sql
-- ❌ 错误写法
SELECT * FROM users WHERE balance > AVG(balance);
```

where后面不能跟聚合函数

**解决思路：**

**第一步：** 先算出平均值是多少。

- `SELECT AVG(balance) FROM users;` -> 假设算出是 350.

**第二步：** 再查谁的钱 > 350。

- `SELECT * FROM users WHERE balance > 350;`

#### 4.3.2 子查询一步到位

我们可以把第一步的 SQL **“塞进”** 第二步的括号里，这就叫子查询。

```sql
-- 任务：查询余额高于平均值的用户
SELECT * FROM users 
WHERE balance > (
    SELECT AVG(balance) FROM users  -- 这里就是子查询，它会先算出一个数字
);
```

### 4.4 数据库设计范式

#### 4.4.1 核心法则：三种人际关系

**① 一对多 (One-to-Many, 1:N) —— 最常见**

- **例子：** 用户 (`users`) 和 订单 (`orders`)。
- **逻辑：** 一个用户可以下 100 个单，但一个订单只能属于 1 个用户。
- **设计口诀：** **“在‘多’的那一边加外键”。**
  - 所以在 `orders` 表里加 `user_id`，而不是在 `users` 表里加 `order_id`。

**② 一对一 (One-to-One, 1:1) —— 也不少见**

- **例子：** 用户 (`users`) 和 身份证详情 (`user_passport`)。
- **逻辑：** 一个人只有一个身份证，一个身份证也只对应一个人。
- **为什么拆开？** 有时候“身份证图片”太大了，平时查用户信息不需要它，为了查得快，把它拆到另一张附表里。

**③ 多对多 (Many-to-Many, N:N) —— 难点**

- **例子：** **学生 (`student`) 和 课程 (`course`)**。
- **逻辑：**
  - 张三选了：Java课、MySQL课。（一个学生对应多门课）
  - Java课里有：张三、李四、王五。（一门课对应多个学生）

一对一和一对多都比较简单，我们直接开始多对多：

**解决思路：引入第三张表（中间表/关联表）：**

**最终结构是 3 张表：**

1. **学生表 (`student`):** 只存学生信息 (id, name)。

#### 4.4.2 做一个小demo

> **任务清单：**
>
> 1. **建表 A：** `student` (列：`id` 主键自增, `name`)
> 2. **建表 B：** `course` (列：`id` 主键自增, `title`)
> 3. **建表 C (关键)：** `score_table` (成绩表/选课表)
>    - 列：`student_id` (整数)
>    - 列：`course_id` (整数)
>    - 列：`score` (整数，代表这门课考了多少分)
>    - *提示：这张表其实就是中间表，顺便还记了个分数。*
>
> **建好后，请模拟以下数据（用 INSERT）：**
>
> - 学生：张三、李四
> - 课程：Java、MySQL
> - **选课情况：**
>   - 张三 选了 Java (考了 90 分)
>   - 张三 选了 MySQL (考了 85 分)
>   - 李四 选了 Java (考了 60 分)
>
> **最后一步：** 写一个 SQL 查询：**查出“张三”选的所有课程名称和分数。** *(这需要用到 3 表关联，或者 2 次 JOIN)*

**示例代码：**

```sql
-- ==========================================
-- 1. 建表阶段 (DDL)
-- ==========================================

-- 1.1 学生表 (Student)
CREATE TABLE student (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50)
);

-- 1.2 课程表 (Course)
CREATE TABLE course (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(50)
);

-- 1.3 成绩表/关联表 (Score) - 这是一个典型的“中间表”
CREATE TABLE score_table (
    student_id INT,
    course_id INT,
    score INT
    -- 在实际生产中，通常还会把 (student_id, course_id) 设为联合主键
);

-- ==========================================
-- 2. 数据准备阶段 (DML)
-- ==========================================

-- 2.1 插入学生
INSERT INTO student (name) VALUES ('ZhangSan'); -- id 会自动变成 1
INSERT INTO student (name) VALUES ('LiSi');     -- id 会自动变成 2

-- 2.2 插入课程
INSERT INTO course (title) VALUES ('Java');     -- id 会自动变成 1
INSERT INTO course (title) VALUES ('MySQL');    -- id 会自动变成 2

-- 2.3 选课打分 (建立关联)
-- 张三(id=1) 选 Java(id=1) -> 90分
INSERT INTO score_table (student_id, course_id, score) VALUES (1, 1, 90);

-- 张三(id=1) 选 MySQL(id=2) -> 85分
INSERT INTO score_table (student_id, course_id, score) VALUES (1, 2, 85);

-- 李四(id=2) 选 Java(id=1) -> 60分
INSERT INTO score_table (student_id, course_id, score) VALUES (2, 1, 60);

-- ==========================================
-- 3. 终极查询 (3表关联)
-- ==========================================
-- 目标：查出 "ZhangSan" 选的所有课程名称和分数
SELECT 
    student.name AS 学生名, -- 逻辑外键
    course.title AS 课程名,
    score_table.score AS 分数
FROM student
-- 第一步：先拿 学生表 连上 中间表
JOIN score_table -- join是inner join的简写
    ON student.id = score_table.student_id
-- 第二步：再拿 中间表 连上 课程表
JOIN course 
    ON score_table.course_id = course.id
-- 第三步：筛选张三
WHERE student.name = 'ZhangSan';
```

#### 5.1.3 代码实战

在 `src/main/java` 下新建一个类 `JdbcHello.java`，把下面的代码复制进去。 **注意修改代码里的 `password` 为你自己的数据库密码。**

```Java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.Statement;

public class JdbcHello {
    public static void main(String[] args) throws Exception {
        // 1. 准备连接信息
        // url 格式: jdbc:mysql://IP地址:端口/数据库名?参数
        String url = "jdbc:mysql://localhost:3306/test1?useSSL=false&serverTimezone=UTC";
        String user = "root";      // 你的 MySQL 用户名
        String password = "YOUR_PASSWORD"; // 数据库密码

        System.out.println("正在连接数据库...");

        // 2. 建立连接 (Connection) —— 相当于打开了 DBeaver
        Connection conn = DriverManager.getConnection(url, user, password);
        System.out.println("连接成功！");

        // 3. 创建执行者 (Statement) —— 相当于打开了 SQL 编辑器窗口
        Statement stmt = conn.createStatement();

        // 4. 发送 SQL 并获取结果 (ResultSet) —— 相当于点击了“执行”按钮
        String sql = "SELECT * FROM users";
        ResultSet rs = stmt.executeQuery(sql);

        // 5. 处理结果集 —— 相当于一行一行看 Excel
        System.out.println("--- 查询结果 ---");
        while (rs.next()) {
            // rs.next() 就像是在表格里按“下箭头”，移动到下一行
            int id = rs.getInt("id");             // 获取 id 列
            String name = rs.getString("username"); // 获取 username 列
            double balance = rs.getDouble("balance"); // 获取 balance 列

            System.out.println(id + " | " + name + " | " + balance);
        }

        // 6. 释放资源 (打完收工，关闭连接)
        rs.close();
        stmt.close();
        conn.close();
    }
}
```

#### 5.1.4 报错提示

假如遇到了报错Public Key Retrieval is not allowed，先别急，这是在 DBeaver 设置里让你勾选 `allowPublicKeyRetrieval=TRUE`导致的，现在在代码里我们需要显式地告诉Java允许去公钥，将url改为如下：

```Java
String url = "jdbc:mysql://localhost:3306/test1?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true";
```

**Q：为什么会这样？**

A：MySQL会用sha2哈希你的密码，所以Java 驱动需要找 MySQL 服务器要一把“钥匙”（公钥）。但是，因为设置了 `useSSL=false`（不使用加密通道），驱动觉得“在不安全的通道上传递钥匙太危险了”，于是默认拒绝执行。加上的 `allowPublicKeyRetrieval=true` 就是强制告诉驱动：“没事，这是我本地环境，允许你去拿钥匙！”

### 5.2 防止sql注入

#### 5.2.1 简单介绍一下sql注入

假如你要查“名字叫 ZhangSan 的人”，你可能会这样写 SQL：

```Java
// ❌ 及其危险的写法：字符串拼接
String name = "ZhangSan";
String sql = "SELECT * FROM users WHERE username = '" + name + "'";
```

如果这个 `name` 是用户在网页输入框里填写的。黑客不填 `ZhangSan`，而是填了一个奇怪的字符串： `ZhangSan' OR '1'='1`

sql就会变成这样：

```sql
SELECT * FROM users WHERE username = 'ZhangSan' OR '1'='1'
```

因为 `'1'='1'` 永远是真的，数据库会**把所有用户的资料全部吐出来**！如果这是登录功能，骇客不需要密码就能直接登录管理员账号。

#### 5.2.2 解决办法

Java 提供了一个更高级的工具 `PreparedStatement`，它用 **`?`** 来占位，坚决不准你在 SQL 语句里拼接字符串。

- **旧方式 (Statement):** 先拼接字符串 -> 发给数据库 -> 数据库编译执行。
- **新方式 (PreparedStatement):** 先把带 `?` 的模板发给数据库编译 -> 再把数据填进 `?` 里。
  - *数据库会把填进去的东西严格当成“纯文本”，绝对不会把它当成命令执行。*

**代码示例：**

在 `src/main/java` 下新建一个类 `JdbcSafeQuery.java`：

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement; //我们要用这个更厉害的
import java.sql.ResultSet;

public class JdbcSafeQuery {
    public static void main(String[] args) throws Exception {
        // 1. 连接数据库 (跟昨天一样，记得改密码！)
        String url = "jdbc:mysql://localhost:3306/test1?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true";
        String user = "root";
        String password = "YOUR_PASSWORD"; // 改密码

        Connection conn = DriverManager.getConnection(url, user, password);

        // ==========================================
        // 2. 准备 SQL 模板 (用 ? 占位)
        // ==========================================
        // 我们要查：余额 > ? 且 城市 = ? 的用户
        String sql = "SELECT * FROM users WHERE balance > ? AND city = ?";

        // 3. 创建预编译执行者
        PreparedStatement pstmt = conn.prepareStatement(sql);

        // 4. 填空 (给 ? 赋值)
        // 第一个 ? 填 100.0 (查余额大于100的)
        pstmt.setDouble(1, 100.0); 
        // 第二个 ? 填 'Beijing' (查北京的)
        pstmt.setString(2, "Beijing");

        System.out.println("即将执行的 SQL: " + pstmt.toString()); // 看看它长啥样

        // 5. 执行查询 (注意：这里不需要再传 sql 字符串了，因为上面已经传过了)
        ResultSet rs = pstmt.executeQuery();

        // 6. 打印结果
        System.out.println("--- 查询结果 ---");
        while (rs.next()) {
            String name = rs.getString("username");
            double balance = rs.getDouble("balance");
            String city = rs.getString("city"); // 别忘了我们之前加了 city 列
            System.out.println("用户: " + name + " | 余额: " + balance + " | 城市: " + city);
        }

        // 7. 释放资源
        rs.close();
        pstmt.close();
        conn.close();
    }
}
```

### 5.3 Java修改数据库

#### 5.3.1 executeQuery vs executeUpdate

在 JDBC 里，方法分两类：

- **`executeQuery()`**: 用于 `SELECT`。它会返回一个 `ResultSet`（一张表），让你慢慢读。
- **`executeUpdate()`**: 用于 `INSERT`, `UPDATE`, `DELETE`。
  - 它**不返回**表格（因为没东西可查）。
  - 它**只返回一个整数 (int)**：代表**“影响了多少行”**。
  - *比如：删了 1 个人，就返回 1；删了 0 个人，返回 0。*

**代码示例：**

在 `src/main/java` 下新建一个类 `JdbcModify.java`：

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;

public class JdbcModify {
    public static void main(String[] args) throws Exception {
        // 1. 连接数据库
        String url = "jdbc:mysql://localhost:3306/test1?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true";
        String user = "root";
        String password = "YOUR_PASSWORD"; //  改密码

        Connection conn = DriverManager.getConnection(url, user, password);

        // ==========================================
        // 任务 A: 新增一个用户 (INSERT)
        // ==========================================
        String sqlInsert = "INSERT INTO users (username, balance, city) VALUES (?, ?, ?)";
        PreparedStatement pstmt1 = conn.prepareStatement(sqlInsert);
        
        // 填空
        pstmt1.setString(1, "Elon");    // 名字
        pstmt1.setDouble(2, 50.0);      // 余额
        pstmt1.setString(3, "NewYork"); // 城市 (随便填)

        // ⚠️ 关键点：这里用 executeUpdate，返回受影响行数
        int rows = pstmt1.executeUpdate();
        System.out.println("成功插入了 " + rows + " 行数据！");

        // ==========================================
        // 任务 B: 修改他的余额 (UPDATE)
        // ==========================================
        String sqlUpdate = "UPDATE users SET balance = ? WHERE username = ?";
        PreparedStatement pstmt2 = conn.prepareStatement(sqlUpdate);

        // 填空
        pstmt2.setDouble(1, 666.6); // 新余额
        pstmt2.setString(2, "Elon"); // 改谁？

        // 执行
        int rows2 = pstmt2.executeUpdate();
        System.out.println("成功修改了 " + rows2 + " 行数据！");

        // 释放资源
        pstmt1.close();
        pstmt2.close();
        conn.close();
    }
}
```

### 5.4 事务控制

#### 5.4.1 场景引入

假设 **ZhangSan** 要给 **LiSi** 转账 100 元。 这在数据库里其实是**两步操作**：

1. **第一步：** ZhangSan 的余额减去 100 (`UPDATE ... SET balance = balance - 100`).
2. **第二步：** LiSi 的余额加上 100 (`UPDATE ... SET balance = balance + 100`).

**💀 恐怖故事：** 如果程序执行完 **第一步** 之后，突然断电了、报错了、或者服务器炸了……

- **结果：** ZhangSan 的钱少了，但 LiSi 的钱没增加。这 100 块钱凭空消失了！
- 这就是所谓的 **“数据不一致”**。

#### 5.4.2 事务介绍

数据库提供了一个机制叫 **事务**。它的核心逻辑是 **“同生共死”**：

- 要么 **全部成功** (Commit)。
- 要么 **全部失败** (Rollback) —— 哪怕做到了 99% 报错了，也要撤销回原点，当做什么都没发生过。

在 JDBC 中，默认是 **自动提交 (AutoCommit)** 的。也就是你执行一行 `executeUpdate`，它就立马生效，无法反悔。 我们要手动关掉它，自己控制命运。

#### 5.4.3 代码示例

1. ZhangSan 扣钱（成功）。
2. **搞个破坏**（手动写个除以 0 的异常 `1/0`，模拟程序崩溃）。
3. LiSi 加钱（还没来得及执行）。
4. **观察：** 如果没有事务，钱就丢了；有了事务，钱应该会**回滚**回来。

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public class JdbcTransaction {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/test1?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true";
        String user = "root";
        String password = "YOUR_PASSWORD"; // ⚠️ 记得改密码

        Connection conn = null;
        try {
            conn = DriverManager.getConnection(url, user, password);

            // ==========================================
            // 1. 开启事务 (关掉自动提交)
            // ==========================================
            // 这句话就是告诉 MySQL：从现在开始，我不说 Commit，你就别真改！
            conn.setAutoCommit(false);

            System.out.println("--- 转账开始 ---");

            // ==========================================
            // 2. 第一步：ZhangSan 扣钱
            // ==========================================
            String sql1 = "UPDATE users SET balance = balance - ? WHERE username = ?";
            PreparedStatement pstmt1 = conn.prepareStatement(sql1);
            pstmt1.setDouble(1, 100.0);
            pstmt1.setString(2, "ZhangSan");
            pstmt1.executeUpdate();
            System.out.println("步骤1：ZhangSan 扣款成功 (但在内存里，还没入库)");

            // ==========================================
            // 3. 模拟意外！(比如断电、代码Bug)
            // ==========================================
            System.out.println("步骤2：突然发生异常...");
            int error = 1 / 0; // ⚠️ 这里会抛出 ArithmeticException，直接跳到 catch

            // ==========================================
            // 4. 第二步：LiSi 加钱 (这行代码永远不会执行)
            // ==========================================
            String sql2 = "UPDATE users SET balance = balance + ? WHERE username = ?";
            PreparedStatement pstmt2 = conn.prepareStatement(sql2);
            pstmt2.setDouble(1, 100.0);
            pstmt2.setString(2, "LiSi");
            pstmt2.executeUpdate();

            // ==========================================
            // 5. 提交事务 (如果没有报错，走到这里才算真正生效)
            // ==========================================
            conn.commit();
            System.out.println("转账成功！");

        } catch (Exception e) {
            // ==========================================
            // 6. 异常处理：回滚 (Rollback)
            // ==========================================
            System.out.println("！！！发生严重错误，准备回滚！！！");
            e.printStackTrace(); // 打印报错信息
            try {
                if (conn != null) {
                    conn.rollback(); // ⏪ 时间倒流！撤销刚才所有的操作
                    System.out.println("--- 已回滚，钱没丢 ---");
                }
            } catch (SQLException ex) {
                ex.printStackTrace();
            }
        } finally {
            // 7. 恢复现场 & 关闭连接
            try {
                if (conn != null) {
                    conn.setAutoCommit(true); // 好习惯：还原默认设置
                    conn.close();
                }
            } catch (SQLException e) {
                e.printStackTrace();
            }
        }
    }
}
```

### 5.5 实体类

从 **“面向过程” (处理零散数据)** 到 **“面向对象” (处理完整对象)** 

我们不想每次都写`Connection`, `PreparedStatement`, `ResultSet`...来连接，也不想查出来的数据是 `rs.getInt("id")`, `rs.getString("username")`... 拿到手的是零散的数据，而不是一个完整的“用户对象”。我们更希望拿到的是一个 `User` 对象，可以直接 `user.getBalance()`。

#### 5.4.1 ORM

我们需要在 Java 代码里建立一个 **类 (Class)**，跟数据库里的 **表 (Table)** 一一对应。

- **数据库表：** `users`
- **Java 类：** `User`
- **表里的一行数据** = **User 类的一个对象 (new User)**

#### 5.4.2 实战

在 `src/main/java/com/example` 下新建一个类，叫 `User.java`。 *(注意：这个类只用来存数据，不写业务逻辑，我们通常叫它 POJO 或 Entity)*：

```java
package com.example; // 确保你的包名对

// 这个类就是 users 表在 Java 世界的“替身”
public class User {
    // 1. 属性名最好和数据库列名保持一致 (驼峰命名法)
    private int id;
    private String username;
    private double balance;
    private String city;

    // 2. 必须提供空参构造器 (MyBatis 以后会用到)
    public User() {
    }

    // 3. 提供全参构造器 (方便我们 new 对象)
    public User(int id, String username, double balance, String city) {
        this.id = id;
        this.username = username;
        this.balance = balance;
        this.city = city;
    }
```

### 5.5 MyBatis-Plus (MP)

> **“把简单的事情留给框架，把复杂的事情留给 SQL。”**

#### 5.5.1 基础介绍

**1.什么是Spring Boot？**

以前要连数据库，需要自己去写连接代码 (`DriverManager.getConnection`)。 你要读配置？你自己去解析 `.ini` 或 `.xml` 文件。 你要管理对象？你自己 `new User()`, `new Manager()`。

有了Spring Boot之后，只要在配置文件里写一句 `password=123456`，Spring Boot 这个管家就会自动看到，并在后台帮你把数据库连好。 **它的核心作用：** 管理所有的**杂活**（连接数据库、启动服务器、管理对象），让你只专注于写业务逻辑。

**2.什么是 MyBatis-Plus？—— “SQL 翻译官”**

**JDBC ：** 需要手写 SQL：`"SELECT * FROM users WHERE id = ?"`。 你需要手动把查出来的结果塞进对象：`user.setId(rs.getInt("id"))`。 **缺点：** 只要数据库表改了一个字段，你得改好几处代码。

**MyBatis-Plus (MP)：** 它是一个**ORM 框架**（Object-Relational Mapping）。 **原理：** 你告诉它“User 类对应 users 表”，它就懂了。 当你调用 `userMapper.selectById(1)` 时，**MP 会自动在后台帮你生成 SQL 语句** `SELECT * FROM users WHERE id = 1`，并且**自动**把结果封装成 `User` 对象给你。 **它的核心作用：** 让你不再需要手写简单的 SQL，也不用手动封装数据。

**3.什么是“注解” (`@xxx`)？—— “便利贴”**

C++ 里很少见这种东西，但在 Java 框架里到处都是以 **`@`** 开头的代码，比如 `@Test`, `@Autowired`, `@Mapper`。

**你可以把“注解”想象成“便利贴”或者“标签”。**

Java 代码本身是静态的，Spring Boot 这个“管家”在巡视代码时，会看这些“标签”来决定做什么。

- **`@SpringBootApplication`**
  - **位置：** 放在启动类头上。
  - **意思：** “管家你看好了，这里是整个程序的入口（大门），从这里开始启动！”
- **`@Mapper`**
  - **位置：** 放在接口 `UserMapper` 头上。
  - **意思：** “管家注意，这是一个专门操作数据库的家伙，请你帮我自动生成它的实现代码（代理），我懒得写了。”即使这是一个空接口，但加上标签后，MyBatis-Plus 会自动赋予它“增删改查”的能力。
- **`@Test`**
  - **位置：** 放在测试方法头上。
  - **意思：** “测试运行器注意，这是一个测试用例，请运行它。”
- **`@Autowired` (最重要！)**
  - **背景：** 在 Spring 里，我们不提倡自己 `new UserMapper()`。
  - **意思：** “管家，我现在需要用 `UserMapper` 这个工具。请你从你的工具箱里找一个已经做好的实例，**自动注入**（Auto Wire）给我。”
  - *这就是大名鼎鼎的“依赖注入” (Dependency Injection)，简单说就是：**我不造轮子，我伸手要轮子**。*

**4.包是什么？**

简单来说，**`com.example.mpdemo` 就是你的代码在 Java 世界里的“家庭住址”**。

Java 要求所有的代码文件（`.java`）都必须放在包（Package）里，就像照片要分类放在不同的文件夹里一样，防止乱套。

Java 业界有一个不成文的规定：**使用公司的域名的“反写”作为包名**。这样是为了全球唯一，我们写了一个类User，那`com.example.mpdemo.User` 就属于 example 公司的 mpdemo 项目。

### 5.6 MyBatis-Plus 的增删改

#### 5.6.1 雪花算法

在测试增加功能时发现新增的id是个负数，为什么？

**现象：** 当不告诉 MP 怎么生成 ID 时，它默认使用 **“雪花算法”**。

**原理：** 它会在 Java 内存里算出一个全球唯一的、超级长的数字（比如 `1728394857...`）直接塞给数据库。

**为什么是负数？** 因为那个数字太大了，超过了 `Integer` (int) 的最大范围，导致“爆表”变成了负数（溢出）。

**解决办法：** **修改 `src/main/java/com/example/mpdemo/User.java`：** 给 `id` 字段加一个注解 `@TableId`。

### 5.7 QueryWrapper —— 让查询“长了脑子”

#### 5.7.1 条件构造器Wrapper

把它想象成一个 **“装条件的箱子”**。

- 你往箱子里放一个 `city = Beijing`。
- 再放一个 `balance > 100`。
- 最后把箱子递给 `userMapper`，它就会自动生成带 `WHERE` 的 SQL。

#### 5.7.2 LambdaQueryWrapper (推荐写法)

MP 提供了两种写法，**工业界最常用、最安全**的一种：**Lambda写法**。

- *好处：不用手写 "city" 这种字符串（容易写错），而是用 `User::getCity`（写错编译器直接报错）。*

请在 `UserTest.java` 中添加 `testWrapper` 方法：

```java
import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper; // 别导错包

// ... Inside UserTest class ...

    @Test
    public void testWrapper() {
        System.out.println("----- 测试复杂条件查询 -----");

        // 1. 创建一个“条件箱子”
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();

        // 2. 往箱子里塞条件
        // 语法：.eq(列名, 值) -> 等于
        //       .gt(列名, 值) -> 大于 (Great Than)
        //       .ge(列名, 值) -> 大于等于 (Great Equal)
        //       .lt(列名, 值) -> 小于 (Less Than)
        //       .like(列名, 值) -> 模糊查询 (包含)
        
        wrapper.eq(User::getCity, "Beijing")   // 城市 = Beijing
               .ge(User::getBalance, 100.0)    // 余额 >= 100.0
               .orderByDesc(User::getBalance); // 按余额降序 (从大到小)

        // 3. 把箱子交给 Mapper 去执行
        List<User> users = userMapper.selectList(wrapper);

        // 4. 打印结果
        users.forEach(System.out::println);
    }
```

### 6.2 JSON

昨天我们返回的是一句话（字符串）。但在真实开发中，前端（Vue/React/App）找后端要的通常不是句子，而是 **数据**。 **JSON (JavaScript Object Notation)** 就是目前全世界最通用的数据格式。

#### 6.2.1 目标

把我们数据库里的用户表，变成下面这种格式发给浏览器：

```json
[
  {"id": 1, "username": "ZhangSan", "balance": 200.0, "city": "Beijing"},
  {"id": 2, "username": "LiSi", "balance": 500.0, "city": "Beijing"}
]
```

我们不需要写代码把 User 对象拼成这种字符串， Spring Boot 有一个特性： 只要你的 Controller 方法返回的是一个 **Java 对象**（比如 `User` 或 `List<User>`），它会自动把它转换成标准 **JSON** 格式。

#### 6.2.2 代码示例

我们不要把代码都塞在 `HelloController` 里，我们要建一个专门管理用户的控制器，在 `com.example.mpdemo.controller` 包下，新建 `UserController.java`：

```java
package com.example.mpdemo.controller;

import com.example.mpdemo.User;
import com.example.mpdemo.UserMapper;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/user") // 给这个类的所有接口加个前缀，比如 /user/list
public class UserController {

    // 1. 注入 Mapper (管家，帮我把操作数据库的工具拿来)
    @Autowired
    private UserMapper userMapper;

    // 2. 查询所有用户接口
    // 浏览器访问地址：http://localhost:8080/user/list
    @GetMapping("/list")
    public List<User> getAllUsers() {
        // 直接调用 MP 的查询方法
        List<User> users = userMapper.selectList(null);
        
        // 重点：我直接返回 Java List，Spring Boot 会自动帮我转成 JSON！
        return users;
    }
}
```

同样的运行服务器，在浏览器输入http://localhost:8080/user/list

**Q：数据是如何流动的？**

**浏览器 (顾客)** ➔ **Controller (服务员)** ➔ **Mapper (后厨)** ➔ **Database (仓库)**

在浏览器发出请求之后Spring Boot 会一直在监听（8080端口），当请求进来时，它会看你贴的注解：`@RequestMapping("/user")` + `@GetMapping("/list")` = **`/user/list`**，Spring 发现地址对上了，立马调用 `getAllUsers()` 方法。

然后UserMapper接口开始工作，核心魔法是`@Autowired` (自动注入)， Controller 不需要知道 Mapper 是怎么做饭的，它只管调用 `selectList()`。

紧接着UserMapper.java开始工作（Mapper ➔ MyBatis-Plus），虽然 `UserMapper` 只是一个空接口，但它继承了 `BaseMapper<User>`， MyBatis-Plus 在程序启动时，利用 **Java 动态代理技术**，自动帮你生成了这个接口的“实现类”，它把 `selectList(null)` 翻译成了 SQL 语句：`SELECT id, username... FROM users`。

其次**`MySQL` 驱动** + **`application.properties`**开始工作，MyBatis 拿着你`application.properties` 里写的 URL、账号、密码，通过 JDBC连上了 MySQL，执行了 SQL 语句。

然后User.java开始工作，orm映射将查出来的第一列 `id` ➔ 塞进 `User` 对象的 `id` 属性，查出来的第二列 `username` ➔ 塞进 `User` 对象的 `username` 属性。此时，内存里有了一个 `List<User>`，里面装着具体的对象。

最后json序列化（Controller ➔ Browser），`UserController` 拿到 `List<User>` 后，直接 `return` 了。Spring Web 内置了一个组件（叫 Jackson），它发现你要把 Java 对象返回给浏览器，它会自动把 Java 对象转换成 **JSON 字符串**（就是你在网页上看到的那堆 `{...}`）。

### 6.3 浏览器传参

#### 6.3.1 介绍

网址： `https://www.baidu.com/s?wd=Java`

- `?` 后面跟着的就是 **参数**。
- 格式是：`key=value`。
- 如果有多个参数，用 `&` 连接：`?username=Trump&city=USA`。

Spring Boot 非常聪明，它能自动把 URL 里这些 `username`、`city` 抓取出来，直接塞给你的 Java 方法参数。

#### 6.3.1 编写注册接口

写一个接口，让用户通过访问 URL 来添加用户，修改`UserController.java`，添加 `addUser` 方法：

```java
// 3. 新增用户接口
    // 浏览器访问：http://localhost:8080/user/add?username=Trump&balance=1000&city=USA
    @GetMapping("/add")
    public String addUser(String username, Double balance, String city) {
        
        // 1. 创建 User 对象
        User user = new User();
        user.setUsername(username);
        user.setBalance(balance);
        user.setCity(city);

        // 2. 存入数据库 (调用 MP)
        userMapper.insert(user);

        // 3. 返回给浏览器一句话
        return "注册成功！新用户 ID 为：" + user.getId();
    }
```

### 6.4 专业级 API —— @RequestBody & POST

后端开发中最标准的数据传输方式：**JSON Body**。把数据打包成一个整洁的 JSON 包裹，通过 **POST** 请求秘密发送给服务器，而不是挂在 URL 上招摇过市。

#### 6.4.1 改造代码

修改 `UserController.java` 里的 `addUser` 方法。

`@GetMapping` $\to$ **`@PostMapping`** (专门用于新增数据)。

参数列表 $\to$ **`@RequestBody User user`** (告诉 Spring：去请求体里找 JSON，自动拼成 User 对象)。

```java
// 3. 【升级版】新增用户接口
    // 这里的地址还是 /user/add，但动作变了
    @PostMapping("/add")
    public String addUser(@RequestBody User user) {
        // 你看，代码变得多干净！不需要一个个写 (String username, double balance...)
        // Spring 既然已经帮我们拼好了 User 对象，我们直接塞给数据库就行
        userMapper.insert(user);
```

### 6.5 三层架构

`UserController` 干了太多的活：它既要接待客人（接收 HTTP 请求），又要直接指挥后厨（调用 Mapper 操作数据库）。

**在企业级开发中，这是不允许的。** 如果逻辑复杂了（比如：注册前要检查用户名是否重复、密码要加密、余额不能是负数），全写在 Controller 里，代码会乱成一锅粥。

需要引入**第三个角色**：**Service (业务逻辑层)**。

#### 6.5.1 MVC

将代码明确分工：

1. **Controller (服务员)：** 只负责收钱、上菜（接收参数、返回 JSON）。**不处理业务！**
2. **Service (大厨)：** 负责切菜、炒菜、加盐（逻辑判断、计算、检查）。
3. **Mapper (采购/库管)：** 只负责去仓库拿食材（读写数据库）。

#### 6.5.2 代码示例

在 `com.example.mpdemo` 下新建一个包 **`service`**，在里面新建类 **`UserService.java`**。

```java
package com.example.mpdemo.service;

import com.example.mpdemo.User;
import com.example.mpdemo.UserMapper;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.List;

// @Service: 告诉 Spring，我是“大厨”，里面写的是核心业务逻辑
@Service
public class UserService {

    // Service 层依赖 Mapper 层（大厨需要找库管要食材）
    @Autowired
    private UserMapper userMapper;

    /**
     * 业务逻辑：查询所有用户
     */
    public List<User> queryAll() {
        // 这里以后可以加逻辑，比如：只查活跃用户、对敏感数据打码等
        return userMapper.selectList(null);
    }

    /**
     * 业务逻辑：注册新用户
     * 这里我们要加点“料”：防止黑客注册负数余额
     */
    public String register(User user) {
        // 1. 逻辑检查 (Business Logic)
        if (user.getBalance() < 0) {
            return "注册失败：余额不能为负数！";
        }

        // 2. 检查通过，才放行给数据库
        userMapper.insert(user);
        return "注册成功！ID: " + user.getId();
    }
}
```

改造`UserController`，`UserController` 不需要认识 `UserMapper` 了，它只需要认识 `UserService`。

```java
package com.example.mpdemo.controller;

import com.example.mpdemo.User;
import com.example.mpdemo.service.UserService; // 引入 Service
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/user")
public class UserController {

    // 1. 以前注入的是 Mapper，现在改成注入 Service
    @Autowired
    private UserService userService; 

    @GetMapping("/list")
    public List<User> getAllUsers() {
        // 以前：直接找 Mapper
        // 现在：找 Service 拿数据
        return userService.queryAll();
    }

    @PostMapping("/add")
    public String addUser(@RequestBody User user) {
        // 以前：直接 insert
        // 现在：交给 Service 去处理（Service 会帮我们检查余额）
        return userService.register(user);
    }
}
```

### 6.6 统一接口格式

#### 6.6.1 避免和前端对线

现在的接口返回的数据五花八门：

- 成功时返回 JSON 列表 `[{...}, {...}]`。
- 注册成功时返回字符串 `"注册成功..."`。
- 失败时返回字符串 `"注册失败..."`。

**前端会疯掉的。** “我怎么知道返回的字符串是成功还是失败？难道要我写代码去判断这句话里有没有‘失败’两个字吗？”

**企业级标准 (`Result` 模式)：** 无论发生什么，后端永远返回一个**固定格式**的 JSON 盒子：

```json
{
  "code": 200,          // 状态码：200代表成功，0或其他代表失败
  "message": "操作成功", // 提示信息
  "data": { ... }       // 真正的数据（比如 User 对象或 List）
}
```

#### 6.6.2 代码示例

第一步：打造盒子 (`Result` 类)

1. 在 `com.example.mpdemo` 下新建包 **`common`** (公共组件)。
2. 在里面新建类 **`Result.java`**。

```java
package com.example.mpdemo.common;

public class Result<T> {
    private Integer code; // 业务状态码：1-成功，0-失败
    private String message; // 提示信息
    private T data;       // 数据

    // 快速生成“成功”结果的方法
    public static <T> Result<T> success(T data) {
        Result<T> result = new Result<>();
        result.code = 1;
        result.message = "success";
        result.data = data;
        return result;
    }

    // 快速生成“失败”结果的方法
    public static <T> Result<T> error(String msg) {
        Result<T> result = new Result<>();
        result.code = 0;
        result.message = msg;
        result.data = null;
        return result;
    }

    // 记得生成 Getter/Setter，否则 Spring 没法转 JSON！
    // (你可以像之前一样用 Alt+Insert 生成，或者手写)
    public Integer getCode() { return code; }
    public void setCode(Integer code) { this.code = code; }
    public String getMessage() { return message; }
    public void setMessage(String message) { this.message = message; }
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}
```

.第二步：让 `UserController` 穿上制服

现在，我们要修改 `UserController`，让所有方法的返回值都变成 `Result<...>`。

```java
package com.example.mpdemo.controller;

import com.example.mpdemo.User;
import com.example.mpdemo.common.Result; // 导入刚才写的 Result
import com.example.mpdemo.service.UserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/user")
public class UserController {

    @Autowired
    private UserService userService;

    // 返回值从 List<User> 变成了 Result<List<User>>
    @GetMapping("/list")
    public Result<List<User>> getAllUsers() {
        List<User> list = userService.queryAll();
        // 用盒子装起来返回
        return Result.success(list);
    }

    // 返回值从 String 变成了 Result<String>
    @PostMapping("/add")
    public Result<String> addUser(@RequestBody User user) {
        // 调用 Service
        String msg = userService.register(user);

        // 判断 Service 返回的是不是 "失败" (这里简单判断一下字符串)
        // 在实际开发中，Service 通常会抛出异常，或者也返回 Result
        if (msg.contains("失败")) {
            return Result.error(msg);
        } else {
            return Result.success(msg);
        }
    }
}
```

#### 6.6.3 关于泛型和static的几个问题

**Q：为什么 `success` 和 `error` 方法要加 `static`？**

**一句话解释：为了方便，不用“先造机器再生产”。**

- **如果不加 `static`（实例方法）：** 你每次想用这两个方法，都必须先 `new` 一个 Result 对象，像这样：

  ```java
  // 麻烦的做法
  Result r = new Result();  // 先造一个空盒子
  return r.success(data);   // 再调用盒子里的方法
  ```

- **加了 `static`（静态/类方法）：** 这就好比是一个**“公共工具”**或**“工厂方法”**。你不需要先造一个对象，直接通过**类名**就能调用：

  ```java
  // 现在的做法（优雅）
  return Result.success(data); 
  ```

  - **比喻：** `static` 方法就像是自动售货机的**按钮**。你不需要自己造一台售货机带回家，你只需要走到公共的售货机面前，按一下按钮，饮料（Result对象）就出来了。

**Q：语法讲解**

`Result<T>` 是**返回值类型**（表示返回一个装着 T 的盒子）。

但是，因为这个方法是 `static` 的，它独立于类存在（不需要 `new` 类）。所以，它**不知道**类上定义的那个 `<T>` 是什么。

因此，我们必须在 `static` 后面、返回值前面，**单独声明一下**：“哎，编译器听着，我马上要用到一个叫 `T` 的泛型，你别报错，它代表任意类型。”

```java
public static <T>      Result<T>      success (T data)
      ↑                   ↑                  ↑
1.声明泛型T       2.返回类型是Result<T>   3.参数也是T
(告诉编译器T是啥)   (最终给出去的东西)      (接收进来的东西)
```

**Q：为什么success返回`Result<List<User>>`，失败返回 `Result<String>`？**

**一句话解释：盒子是一样的（Result），但里面装的礼物（Data）不一样。**

`Result` 类就像一个**顺丰快递盒**。

- `code` 和 `message` 是快递单上的固定信息（状态、备注）。
- `data` 是盒子里的具体物品。

**场景 A：`getAllUsers()`**

- **你的目的：** 给前端一箱子人。
- **数据本体：** `List<User>`。
- **装箱后：** `Result<List<User>>`。
  - *盒子打开，里面是一张人员名单。*

**场景 B：`addUser()`**

- **你的目的：** 只是告诉前端“完事了”，顺便给一句口信。
- **数据本体：** `String` （即 "注册成功..." 这句话）。
- **装箱后：** `Result<String>`。
  - *盒子打开，里面是一张写着字的纸条。*

这就是**泛型**的强大之处：**一套代码 (`Result` 类)，可以包装万物。**

### 6.7 简单的前后端合体

在 `src/main/resources/static` 目录下（如果没有 `static` 文件夹就新建一个），新建一个文件 **`index.html`**：

```html
<!DOCTYPE html>
<html lang="zh">
<head>
    <meta charset="UTF-8">
    <title>我的用户管理系统</title>
    <style>
        body { font-family: sans-serif; padding: 20px; }
        .card { border: 1px solid #ddd; padding: 10px; margin: 10px 0; border-radius: 5px; }
        .success { color: green; }
        .error { color: red; }
    </style>
</head>
<body>

    <h1>🚀 欢迎来到结业展示</h1>

    <div style="background: #f0f0f0; padding: 15px;">
        <h3>注册新用户</h3>
        <input type="text" id="username" placeholder="用户名 (Username)">
        <input type="number" id="balance" placeholder="余额 (Balance)">
        <input type="text" id="city" placeholder="城市 (City)">
        <button onclick="doRegister()">注册</button>
        <p id="msg"></p>
    </div>

    <h3>用户列表 <button onclick="loadUsers()">🔄 刷新列表</button></h3>
    <div id="userList"></div>

    <script>
        // --- 核心逻辑：调用后端 list 接口 ---
        function loadUsers() {
            fetch('/user/list') // 浏览器向你的 Spring Boot 发请求
                .then(response => response.json())
                .then(res => {
                    // res 就是你后端返回的 Result 对象
                    if (res.code === 1) {
                        let html = '';
                        // 遍历 res.data (List<User>)
                        res.data.forEach(user => {
                            html += `<div class="card">
                                <b>ID:</b> ${user.id} | 
                                <b>姓名:</b> ${user.username} | 
                                <b>余额:</b> ${user.balance} | 
                                <b>城市:</b> ${user.city}
                            </div>`;
                        });
                        document.getElementById('userList').innerHTML = html;
                    } else {
                        alert("获取失败：" + res.message);
                    }
                });
        }

        // --- 核心逻辑：调用后端 add 接口 ---
        function doRegister() {
            let data = {
                username: document.getElementById('username').value,
                balance: parseFloat(document.getElementById('balance').value),
                city: document.getElementById('city').value
            };

            fetch('/user/add', {
                method: 'POST', // 指定用 POST 方法
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify(data) // 把 JS 对象转成 JSON 字符串发给后端
            })
            .then(response => response.json())
            .then(res => {
                let msgBox = document.getElementById('msg');
                if (res.code === 1) {
                    msgBox.className = "success";
                    msgBox.innerText = "✅ " + res.data; // 显示"注册成功"
                    loadUsers(); // 注册成功后自动刷新列表
                } else {
                    msgBox.className = "error";
                    msgBox.innerText = "❌ " + res.message; // 显示"余额不能为负"
                }
            });
        }

        // 页面一打开就加载列表
        loadUsers();
    </script>
</body>
</html>
```

这是一个极简的网页，它利用浏览器自带的 `fetch` 功能去调用你的后端接口。

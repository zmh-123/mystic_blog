## 1. 介绍：数据库是什么，为什么要有数据库

数据库本质上就是一个**运行在硬盘上的文件系统**，一般我们自己编写的代码，数据存在List/Map里面，断电或者重启数据就没了，另外普通文件存在硬盘里面，比如说txt或则excel，能保存但是很难查找。而数据库（MySQL）中的数据存在硬盘里，但有一个管家管着，利用索引技术，很快就能找到。

可以用excel来类比下关系型数据库：

| **数据库术语**        | **Excel 对应**              | **说明**                                        |
| --------------------- | --------------------------- | ----------------------------------------------- |
| **Database (数据库)** | **一个 Excel 文件 (.xlsx)** | 比如 `meituan_data.xlsx`                        |
| **Table (表)**        | **Sheet (工作表)**          | 一个文件里可以有“用户表”、“订单表”、“商品表”    |
| **Column (列/字段)**  | **表头 (第一行)**           | 规定了每一列存什么，比如 `Name`, `Age`, `Price` |
| **Row (行/记录)**     | **数据行**                  | 每一行就是一个具体的订单或用户                  |

然后要说明的是，这里是MySQL的学习笔记，另外还有Oracle或者其他一些自研数据库管理工具自行学习即可。

### 3.1 建库建表

**1.创建数据库**：新建->数据库，name自定义，我这里是test1，其他默认。

**2.创建表**：展开test1，邮件点击新建表，创建一张用户表users。

**3.设计列（相当于画表头）----关键**：

在列（Columns）区域右键 -> **新建列 (Create New Column)**，依次添加以下 3 列：

**列名：`id` (用户ID)**

- **类型 (Data Type):** `INT` (整数)。
- **关键设置：** 勾选 **主键 (Primary Key)** 和 **自增 (Auto Increment)**。
  - *解释：主键相当于身份证号，表示它是唯一的。自增意味着你不用管它，数据库会自动填 1, 2, 3...*

**列名：`username` (用户名)**

- **类型:** `VARCHAR` (可变长字符串)。
- **长度:** 写 `50` (表示最多存50个字)。

**列名：`balance` (余额)**

- **类型:** `DOUBLE` 或 `DECIMAL` (小数)。

**4.保存：**创建完成，点击执行。

#### 3.2.1 增 (INSERT) —— 往表里塞数据

我们要往 `users` 表里添加一个用户：张三，余额 100.5 元。

**语法公式：**

```sql
INSERT INTO 表名 (列1, 列2, ...) VALUES (值1, 值2, ...);
```

**实战代码：** 请在 SQL 编辑器里输入以下代码（注意标点符号要用英文）：

```sql
-- 这里的 -- 代表注释
-- 1. 插入第一条数据
-- 注意：我们不需要插入 id，因为之前设置了“自增”，数据库会自动填 1
INSERT INTO users (username, balance) VALUES ('ZhangSan', 100.5);

-- 2. 插入第二条数据
INSERT INTO users (username, balance) VALUES ('LiSi', 500.0);

-- 3. 插入第三条数据 (余额为 0)
INSERT INTO users (username, balance) VALUES ('WangWu', 0);
```

**执行方法：** 选中这三行代码，点击左上角的 **橙色三角形 ▶** (或者按 `Ctrl + Enter`) 执行。 *观察下方的“输出”窗口，如果显示 `Updated Rows: 1` 之类的提示，说明成功了。*

![运行按钮](/images/mysql/sql_2.png)

------

#### 3.2.2 查 (SELECT) —— 看看塞进去没

**语法公式：**

```sql
SELECT * FROM 表名;  -- * 代表“所有列”
```

**实战代码：**

```sql
SELECT * FROM users;
```

**执行方法：** 选中这行代码，运行它。 你下面的结果栏里，应该会出现一张表格，里面有 `ZhangSan`, `LiSi`, `WangWu` 三行数据，而且 `id` 自动变成了 1, 2, 3。

#### 3.2.3 改 (UPDATE) —— 比如张三充值了

我们要把 **ZhangSan** 的余额改成 `200.0` 元。

**警告：不要忘记写 `WHERE`**！

- **错误写法：** `UPDATE users SET balance = 200;` （完蛋了，所有人的钱都变成 200 了）
- **正确写法：** 必须加锁，指定只改某一个人。

**实战代码：**

```sql
-- 任务：把用户名为 'ZhangSan' 的人，余额改为 200
UPDATE users 
SET balance = 200.0 
WHERE username = 'ZhangSan'; 
-- 也可以写 WHERE id = 1; (用 ID 更精准)
```

#### 3.2.4 删 (DELETE) —— 比如王五注销账号了

我们要把 **WangWu** 从表里彻底删掉。

- **错误写法：** `DELETE FROM users;` （完了，全库清空，准备跑路吧）
- **正确写法：** 指定只删某一个人。

**实战代码：**

```sql
-- 任务：删除用户名为 'WangWu' 的记录
DELETE FROM users 
WHERE username = 'WangWu';
```

### 3.3 SQL进阶：筛选排序与分页

#### 3.3.0 准备工作：补充点数据

```sql
INSERT INTO users (username, balance) VALUES ('MaYun', 999999.0);
INSERT INTO users (username, balance) VALUES ('Pony', 888888.0);
INSERT INTO users (username, balance) VALUES ('XiaoMing', 5.5);
INSERT INTO users (username, balance) VALUES ('XiaoHong', 20.0);
```

*(执行完后，你可以 `SELECT \*` 确认一下，现在应该有 6 行左右的数据了)*

------

#### 3.3.1 条件筛选 (`WHERE` 的进阶)

- **场景**：找出所有余额大于 1000 元的“大款”。
- **符号**：`>` (大于), `<` (小于), `>=` (大于等于), `!=` (不等于)。

**实战代码：**

```sql
-- 找出余额大于 500 的用户
SELECT * FROM users 
WHERE balance > 500;
```

------

#### 3.3.2 排序 (`ORDER BY`) —— 谁最有钱？

默认的数据是按 ID 排的，我们想按“余额”排。

- **语法**：`ORDER BY 列名 [ASC|DESC]`
  - **ASC** (Ascending)：升序（从小到大，默认）。
  - **DESC** (Descending)：降序（从大到小）。

**实战代码：**

```sql
-- 按余额从大到小排序（看看谁是首富）
SELECT * FROM users 
ORDER BY balance DESC;
```

------

#### 3.3.3 分页 (`LIMIT`) —— 只看前几名

这是开发**最常用**的语句。手机 App 一页只显示 10 条外卖，就是用这个实现的。

- **语法**：`LIMIT 数量`

**实战代码：**

```sql
-- 找出最有钱的 3 个人 (组合拳：先排序，再取前3)
SELECT * FROM users 
ORDER BY balance DESC
LIMIT 3;
```

结果比较简单，不再展示。

### 3.4 SQL统计与聚合：想看报表怎么办？

> 解决场景：
>
> “咱们现在的用户总共有多少人？”
>
> “用户账户里总共存了多少钱？”
>
> “平均每个用户有多少钱？”
>
> “最有钱的人有多少钱？”

### 3.4.1 核心五大函数

| **函数**    | **英文** | **作用**   | **对应 Excel** |
| ----------- | -------- | ---------- | -------------- |
| **COUNT()** | Count    | **数人头** | `=COUNT()`     |
| **SUM()**   | Sum      | **求和**   | `=SUM()`       |
| **AVG()**   | Average  | **算平均** | `=AVERAGE()`   |
| **MAX()**   | Maximum  | **最大值** | `=MAX()`       |
| **MIN()**   | Minimum  | **最小值** | `=MIN()`       |

### 3.4.2 示例

```sql
-- 统计 users 表里一共有多少行数据
SELECT COUNT(*) FROM users;

-- 一次性查出：总金额 (Total) 和 平均金额 (Average)
-- AS 是给结果列起个中文别名，方便看
SELECT 
    SUM(balance) AS 总金额, 
    AVG(balance) AS 平均金额 
FROM users;

-- 查出最有钱和最穷的余额是多少
SELECT 
    MAX(balance) AS 首富余额, 
    MIN(balance) AS 最穷余额 
FROM users;
```

**进阶：待条件的统计：** 只想看**余额在 1000 元以上**的那些大客户，他们的**平均余额**是多少？

```sql
-- 错误解法：AVG() 是一个计算器，它只负责算数，不负责筛选。你不能把 WHERE（筛选条件）塞进 AVG 的肚子里。
select
	AVG(where BALANCE > 1000) as 大于1000平均
from users;

-- 先筛选再计算
SELECT 
    AVG(balance) AS 大于1000平均 
FROM users 
WHERE balance > 1000;  -- 先筛选，后计算
```

**为什么这里是先筛选后计算？**

对与sql语句来说，sql语法有固定的书写顺序：

```sql
SELECT
DISTINCT
FROM
JOIN
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT` / `OFFSET
```

但是也有固定的执行顺序：

```sql
FROM / JOIN —— 确定数据源
WHERE —— 筛选原始数据（无法使用聚合函数结果）
GROUP BY —— 对筛选后的数据分组
HAVING —— 筛选分组后的结果（可以使用聚合函数结果）
SELECT —— 计算并展示结果（起别名、聚合计算等）
DISTINCT —— 去重最终结果
ORDER BY —— 对最终结果排序
LIMIT / OFFSET —— 限制返回结果的数量
```

### 3.5 分组统计(`GROUP BY`) —— SQL 最强大的功能

> 场景：“别光给我看总平均，我想看 **每个城市** 的用户总资产是多少？是北京的钱多，还是深圳的钱多？”

#### 3.5.1 第一步：数据改造 (DDL)

我们需要先给表“装修”一下，加一列 `city`，并且给每个人分配一个城市。

```sql
-- 1. 给 users 表增加一列 'city'，最多存10个字
ALTER TABLE users ADD city VARCHAR(10);

-- 2. 给大佬们分配城市
UPDATE users SET city = 'Hangzhou' WHERE username = 'MaYun';
UPDATE users SET city = 'Shenzhen' WHERE username = 'Pony';

-- 3. 给剩下的小伙伴分配到 Beijing (一次更新多人)
UPDATE users SET city = 'Beijing' WHERE city IS NULL;

-- 4. 查一下看看效果
SELECT * FROM users;
```

------

#### 第二步：分组查询 (`GROUP BY`)

现在我们要用到 SQL 的灵魂语法：**“按......分组”**。

**语法公式：**

```sql
SELECT 
    分组列名, 
    聚合函数(...) 
FROM 表名 
GROUP BY 分组列名;
```

**任务：统计每个城市的总资产** 请尝试写出这条 SQL：

1. 我们要查的是 `city` 和 `SUM(balance)`。
2. 要按照 `city` 进行分组。

**参考代码：**

```sql
SELECT 
    city AS 城市, 
    SUM(balance) AS 城市总资产 
FROM users 
GROUP BY city;
```
